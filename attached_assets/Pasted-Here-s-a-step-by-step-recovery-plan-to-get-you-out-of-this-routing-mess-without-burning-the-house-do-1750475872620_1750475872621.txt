Here's a step-by-step recovery plan to get you out of this routing mess without burning the house down. This balances technical sanity, team velocity, and risk mitigation.

🎯 YOUR GOAL:
Transform your current routing system into:

A scalable, hierarchical structure

With clear separation of public/auth routes

Using consistent navigation patterns

That’s easy to maintain, debug, and extend

🧭 STEP-BY-STEP PLAN
1. Audit & Group All Existing Routes
Group routes into:

✅ Keep (with/without changes)

❌ Remove (redundant/unused)

🛠️ Refactor (flat → hierarchical)

Use a spreadsheet or table to track:

Route	Component	Auth?	Needs Refactor?	Notes

➡️ This gives you situational awareness before touching code.

2. Define a Clean Route Hierarchy (vNext)
Use the structure from the report’s recommendation:

Public
/ → Landing

/tracks/:trackId

/chapters/:chapterId

Authenticated
/dashboard → RoleTabs

/learning/... → Student

/content-management/... → Internal tooling

/admin/... → Superuser space

Labs

This acts as your single source of truth going forward.

3. Refactor Navigation Logic First
Don't break routes yet. First:

🔁 Replace all window.location.href with router.push() / setLocation()

🧼 Standardize on useParams() for route params

🧭 Normalize forward/backward navigation using a helper or hook

Why now? Because consistent navigation logic lets you move routes later without chaos.

4. Remove & Consolidate Duplicate Routes
Once logic is clean:

❌ Delete /chapter-editor/:chapterId

✅ Migrate usages to /content-management/tracks/:trackId/chapters/:chapterId

Use search-and-replace + redirect stubs if needed to avoid breaking things mid-sprint.

5. Isolate Experimental Routes
Move everything under /experiment1/... into /labs/... or disable entirely if not in use.

✅ Rename /experiment1/segmentation-studio/:chapterId → /labs/segmentation/:chapterId

📦 Later: wrap these behind a feature flag

This reduces pollution and lets you manage unstable code safely.

6. Add Redirects to Catch Old Links (Optional, but Smart)
Use router middleware or fallback routes to catch old paths like:

7. Gradual Rollout + Team Communication
🪧 Create a dev-facing changelog (before/after route mappings)

🧪 Feature flag routing changes for internal testing

🧵 Communicate to all devs: “We are now using this routing standard. All new features must follow it.”
