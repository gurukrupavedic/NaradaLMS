# DD-003: Require an exam target to be enrolled with role exactly `student`

**Status:** approved — implementation gated on the §5 production data check

## 1. Current behavior

Per PARITY_PLAN.md §1.3/§2, the current backend's exam-assignment validation accepts a
target enrolled under **any** role in a qualifying batch (instructor/TA/student all pass),
not just `student`.

## 2. Problem/opportunity

Scheduling an exam against a non-student enrollment (e.g. an instructor's own enrollment
row) is very likely a data-integrity gap in the old backend rather than an intentional
allowance — an exam target should be a student. But PARITY_PLAN.md explicitly calls this
out as a compatibility-baseline item, not a given, because it's plausible some existing
data or caller depends on the looser check.

## 3. Proposed behavior

`createExam`/assignment validation requires the target's enrollment role to be exactly
`student`; any other role (or no enrollment) is rejected with the same 422 message class
already used for invalid assignment (see PARITY_PLAN.md §11.4).

## 4. Alternatives

- **Baseline:** accept enrollment under any role, matching current behavior exactly.
- **Proposed:** require role exactly `student` (current draft direction, per
  `assertValidExamAssignment` intent referenced in `accessPolicy.ts`).

## 5. Impact analysis

Query current production data for any exam whose `studentId` maps to a non-student
enrollment before tightening this — if any exist, tightening would orphan them or require
a backfill decision. Web app impact: none expected (the UI shouldn't let you schedule an
exam for a non-student), but this must be confirmed, not assumed.

## 6. Compatibility/rollout plan

Run the data check above first. If zero non-student exam targets exist today, this is a
same-day validation tightening with no migration. If any exist, this decision is blocked
until they're resolved (reassign or explicitly grandfather).

## 7. Acceptance criteria

Test: create exam against instructor/TA-enrolled target is rejected 422; against
student-enrolled target succeeds; against unenrolled target is rejected (existing
baseline behavior either way).
