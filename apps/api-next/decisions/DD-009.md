# DD-009: Structured JSON 400 for malformed body, JSON 404 for unmatched routes

**Status:** proposed

## 1. Current behavior

Not yet confirmed against `apps/api/src` — PARITY_PLAN.md §6.1/§13.4 treats this as
needing verification: does the current backend return a structured `{ ok: false, error }`
JSON body for malformed request JSON (body-parser `SyntaxError`) and for requests to
unmatched routes under the API version prefix, or does it fall through to Express's
default HTML/plaintext error responses?

## 2. Problem/opportunity

If the current backend already returns Express's default (non-JSON, non-enveloped) error
bodies for these two cases, every other response being a consistent `{ ok, ... }`
envelope while these two are not is an inconsistency worth fixing. If the current
backend already structures these, then this isn't a behavior change at all — just an
implementation gap in the draft to close without a DD.

## 3. Proposed behavior

- Malformed JSON body → 400 `{ ok: false, error: { code: 'INVALID_REQUEST', message } }`
  (via the body-parser `SyntaxError` branch already contemplated in PARITY_PLAN.md
  §13.4 error-middleware ordering).
- Any request to `/v{version}/*` that matches no route → 404 JSON, same envelope shape,
  rather than Express's default fallthrough.

## 4. Alternatives

- **Baseline:** replicate whatever the current backend does today for these two cases,
  even if that's an unstructured/non-JSON body.
- **Proposed:** structured JSON envelope for both (current draft direction, consistent
  with every other error response).

## 5. Impact analysis

Any client currently parsing these specific error responses as non-JSON (unlikely, but
unverified) would need to adapt. Low risk in practice — these are edge/failure paths,
not documented success contracts.

## 6. Compatibility/rollout plan

First verify actual current behavior with a quick manual check (`curl` malformed JSON and
an unmatched route against `apps/api/src` running locally) before treating this as a real
fork — this may collapse to "just implement it," same as DD-007.

## 7. Acceptance criteria

Test: `POST` with unparseable JSON body → 400 with the standard envelope; `GET` to an
undefined path under `/v{version}` → 404 with the standard envelope; both distinguishable
from `AppError`-thrown 400/404s only by message, not by shape.
